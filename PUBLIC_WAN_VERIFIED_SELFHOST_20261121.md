# WAN-проверка пройдена: FotoMag может работать на собственном ПК

21.11.2026 владелец прислал скриншот действующей панели Netis N2Mv2, где виден публичный IPv4 на WAN-интерфейсе PPPoE. **Публичный IPv4 подтверждён; CGNAT на WAN в момент проверки нет.** Адрес роутера и серийные идентификаторы намеренно НЕ публикуются в репозитории.

## Бесплатная схема

Прежняя GitHub Pages страница и QR-код → HTTPS-адрес бесплатного Dynamic DNS (например dynv6) → публичный WAN Netis → только HTTPS reverse proxy на изолированном приёмнике Windows → шлюз файлов с антивирусом → D: архив FotoMag.

Платные VPS/домен/коммерческий туннель технически не обязательны. Сам факт публичного IPv4 **не доказывает**, что провайдер пропускает входящие порты 80/443; проверка остаётся впереди.

Dynv6: https://dynv6.com/ — бесплатный Dynamic DNS, API для обновления записи при смене PPPoE IP: https://dynv6.com/docs/apis

Caddy automatic HTTPS: https://caddyserver.com/docs/automatic-https — публичное DNS-имя, проверка доступа к порту 80/443 и сертификат. Для ограниченного теста Let's Encrypt также выпускает краткосрочные сертификаты непосредственно для IPv4, но с автоматическим продлением раз в несколько дней: https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability

## Проверки Desktop Commander

- Windows PC и D: архив доступны.
- На момент проверки порты 80/443 и ранее использованные тестовые порты не слушают — это нормально, клиентский приём отключён.
- Приватная рабочая конфигурация на ПК отсутствует; сервер не запущен.
- VPN NekoBox/Iblis работает в режиме TUN и перехватывает маршруты; нужно отдельное испытание исходящих ответов сервера с VPN ON/OFF.
- Никаких изменений роутера, VPN, Windows Firewall и рабочих каналов не производилось.
- Подробный отчёт с адресом WAN записан **только локально**: D:/FotoMag_Direct_Upload_Channel/PUBLIC_WAN_CONFIRMED_20261121.txt.

## Блокирующие шаги перед запуском для клиентов

1. Создать бесплатный DDNS-хост и безопасно наладить обновление WAN из роутера, а не брать IP у браузера через VPN.
2. Развернуть изолированный HTTPS приёмник и проверить работу Caddy, DNS и входящих соединений через мобильный интернет. Открывать только необходимые порты, никакого RDP/SMB/общих папок/админки роутера.
3. Подключить подтверждённое сканирование вложений до сохранения в рабочую очередь; действующий 360 Total Security на ПК ещё не даёт подтверждённый API-результат.
4. Завершить правовую политику обработки и хранения персональных данных, исключить реальные документы из тестов.
5. Сначала завершить весь тестовый сценарий с синтетическими JPG/PDF и сверкой SHA-256, затем активировать дизайн А GitHub Pages. Если ПК выключен, сайт показывает недоступность и действующие резервные каналы.
