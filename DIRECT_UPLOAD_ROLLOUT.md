# FotoMag — прямая загрузка фото и документов с QR-страницы

Дата: 21.11.2026. Статус: черновик, НЕ публиковать для клиентов до подключения сервера и приёмочного теста. Текущий сайт GitHub Pages и три канала VK/MAX/Telegram не меняются.

## Маршрут клиента

1. QR → FotoMag → «Отправить файл напрямую».
2. Выбор услуги (фото, документы, фото на документы 450 ₽), до 10 файлов; имя клиента, телефон и комментарий необязательны. Для приёма в магазине достаточно выбрать файл, отметить согласие и отправить. Каждая заявка имеет уникальную квитанцию.
3. Браузер по HTTPS загружает файлы на отдельный сервер в России, показывает прогресс и получает номер заявки вида FM-W-20261121-XXXXXXX.
4. Сервер хранит файлы в непубличной очереди и не выполняет печать.
5. Агент Windows забирает очередь исходящим HTTPS-запросом, проверяет размер и SHA-256 и сохраняет именно в архив 2026 на диске D, внутри существующей структуры дат и канала «Напрямую», в отдельной папке каждого клиента/заказа. Сотрудник подтверждает параметры вручную; сообщение «доставлено на компьютер» появляется только после подтверждения приёмщика.

## Что готово

- Форма в index.html, JS/CSS без сторонних библиотек.
- Защищённый приёмник на FastAPI со SQLite и проверкой сигнатур поддерживаемых форматов.
- Агент для Windows, который не открывает и не печатает файлы, не переписывает уже существующие файлы. Папка на диске D: создаётся внутри указанного существующего архива года, если структура даты подтверждена.
- Проверки безопасности и тесты очереди с искусственными файлами.
- Внешний API пока не указан: meta name=fotomag-upload-api содержит пустую строку, CSP имеет connect-src none, кнопка отправки отключена. Это защита от ложного успеха.

## Перед включением обязательно

1. Отдельный VPS/сервер в России с DNS, HTTPS, мониторингом диска, резервными копиями и обновлениями безопасности; ограничить публичный доступ только портами 80/443.
2. На сервере настроить файл upload_gateway/.env из .env.example: реальный FOTOMAG_API_DOMAIN, FOTOMAG_SITE_ORIGIN и случайный секрет FOTOMAG_AGENT_TOKEN длиной не менее 32 символов. Секрет никогда не помещать в публичный репозиторий и браузер.
3. Подготовить правовую часть: юридическое имя/реквизиты оператора, публичную политику и соответствующее согласие, срок хранения и удаление, организационные меры по 152-ФЗ. Текущая заглушка в форме юридически недостаточна.
4. Настроить лимиты на уровне VPS/WAF, антивирусную проверку документов и карантин, уведомления об ошибках и исчерпании места. Без этого нельзя принимать реальные документы клиентов.
5. Коммандер подключён, архив и Python 3.11 проверены, локальный файл приёмщика установлен и испытан без реальных заказов. **Остаётся** после развёртывания HTTPS-приёмника задать FOTOMAG_API_URL и приватный FOTOMAG_AGENT_TOKEN на ПК, настроить исходящую связь и автозапуск безопасной службы. Не затрагивать MAX, Telegram, VK, принтеры и старые файлы.
6. Испытать искусственные JPEG, HEIC, PDF, DOCX, попытки загрузить EXE и оборванную сеть; проверить номер заявки, получение на ПК, SHA-256 и отсутствие автопечати.
7. Добавить реальный HTTPS API адрес в meta name=fotomag-upload-api, разрешить только его origin в CSP connect-src, заменить заглушку согласия ссылкой на настоящую политику. До этого CI запрещает активацию.
8. Протестировать VK, MAX, Telegram и прямую загрузку отдельно на смартфонах. Затем утверждать публикацию.

## Параметры пилота

- 10 файлов, максимум 25 МиБ каждый и 100 МиБ на одну заявку.
- Форматы: JPG/JPEG, PNG, WEBP, HEIC/HEIF, PDF, DOCX, XLSX.
- Нет онлайн-оплаты и автопечати. Успешная загрузка — не подтверждение стоимости или готовности заказа.
- Данные не хранятся в GitHub.
- Серверный retention и антивирус до промышленного запуска дополнительно согласовать и реализовать.
- **Проверено Коммандером 21.11.2026:** существующий архив D:\2026\11\20\MAX\Karina\FM-20261120-006 и D:\2026\11\20\Telegram\djull\FM-20261120-007 показывает точный формат: год / двузначный месяц / двузначный день / канал / клиент / номер заказа.
- Для «Напрямую» принят такой же порядок:
  D:\2026\11\21\Напрямую\Алексей\FM-W-20261121-A1B2C3D\
  01_photo.jpg, 02_document.pdf, ЗАКАЗ.txt, order.json.
- Параметр FOTOMAG_DATE_SUBPATH по умолчанию = %m/%d; FOTOMAG_ARCHIVE_ROOT = D:\2026. Структуру MAX/Telegram/VK не менять.
- Перед запуском агент требует существующий корень архива на диске D:; он не создаёт новый фиктивный корень «2026» и не перемещает старые данные.

## О скорости открытия страницы

Текущий портал — статический, без внешнего JS и тяжёлых библиотек; клиентский код небольшой. Если проблема — медленный доступ к github.io через провайдера, добавление кнопки не исправит задержку DNS/TLS. Целевой вариант — российский HTTPS-хостинг или зеркало с собственным доменом после замеров с нескольких мобильных операторов. Если QR содержит непосредственно github.io, его полноценная замена новым хостингом может потребовать нового QR-кода. Действующий QR и сайт не меняем на этом этапе.

## Отдельный сценарий самообслуживания

Клиент может не сообщать имя и телефон, если находится у стойки; тогда его папка размещается в «Напрямую/Без_имени/<номер заявки>», а сотрудник может найти поступление по номеру квитанции на телефоне. Номер нужен для сверки без обращения к мессенджерам. На сервере и ПК информация не превращается автоматически в заказ на печать.

## 21.11 — закрытый шлюз и обязательная проверка вложений

В локальном режиме на DESKTOP-P6L7HTI с изолированным Python 3.11 был запущен тестовый HTTP-приёмник, **только на 127.0.0.1:18443**, не доступный извне. Тестовые JPEG и PDF прошли маршрут «заявка → бинарные файлы → отдельная очередь → локальный агент → QA-папка Windows → сверка SHA-256 → ACK». Сквозной тест успешен. Процесс тестового сервера после проверки остановлен. Детали: STAGING_GATEWAY_QA_20261121.md.

**Для рабочего продакшена** добавлены fail-closed условия:
- FOTOMAG_UPLOAD_MODE=disabled по умолчанию. Случайный запуск Docker не должен включать публичный приём.
- FOTOMAG_UPLOAD_MODE=production доступен только при настроенном FOTOMAG_CLAMD_HOST.
- Файлы не передаются агенту, пока серверный ClamAV не подтвердит каждый файл (временная недоступность сканера блокирует заказ, а обнаружение угрозы отклоняет).
- В Docker Compose предусмотрен отдельный контейнер ClamAV, без опубликованного порта 3310; база сигнатур сохраняется в volume.
- Caddy ограничивает тело каждого HTTP-запроса до 26 MB. Ресурсы VPS надо рассчитать: официальный ClamAV может требовать порядка 4 GB RAM. До развёртывания на конкретном сервере протестировать работу актуальных сигнатур.
- FOTOMAG_UPLOAD_MODE=staging разрешён только для локальных и синтетических проверок, не для живых клиентов.

**Ещё отсутствуют** реальный домен/сервер в России, законный текст обработки данных, настроенный режим production, мониторинг/WAF, срок хранения и публичный тест через мобильный интернет. UI в main не опубликован до утверждения дизайна.


## Технический этап: усиленный шлюз (21.11.2026)

По итогам проверки отдельного сервера и рабочего компьютера:

- Docker Desktop на DESKTOP-P6L7HTI выделяет около 3 ГБ для Docker Engine при 64 ГБ физической RAM. По официальным рекомендациям ClamAV предпочтительно 4 ГБ RAM для одного антивируса, поэтому тяжёлый ClamAV **не запускается на рабочем ПК**. Для отдельного российского VPS выбран ориентир 8 ГБ RAM/SSD от 60 ГБ.
- Caddy прошёл синтаксическую проверку в облачном GitHub CI: разрешены только публичные порты 80 и 443, внутренние 8000/3310 не публикуются. Caddy принудительно перезаписывает клиентский IP-заголовок перед передачей на шлюз; API проверяет его и не доверяет пользовательской подмене.
- Суточная квота принятых файлов в пилоте — 5 ГиБ, минимум свободного места на сервере 3 ГиБ. 60 регистраций заявок в час с одного публичного IP, чтобы посетители на общем Wi-Fi не блокировали друг друга. Предусмотрен обязательный дополнительный сетевой антиспам/мониторинг перед публичным запуском.
- Кнопка клиента не активируется только по наличию URL: при открытии формы она запрашивает /api/health и включается лишь при подтверждённом состоянии accepting_uploads=true. Этот статус возможен в production только при живом ответе антивируса на PING. При недоступности шлюза кнопка заблокирована.
- JS формы теперь загружается отложенно, только при открытии окна «Напрямую», чтобы не замедлять первую загрузку QR-страницы. По CI 84 835 байт несжатых стартовых статических ресурсов, 98 043 байта всего приложения без ленивых изображений/шрифтов. Наличие задержек у операторов для github.io этим тестом не проверяется.
- Механизм аварийного отключения блокирует новые заявки, новые загрузки файлов и подтверждение отправки; раньше существующий токен мог продолжить передачу при выключении режима. Исправлено.
- Временная очередь с готовым кодом сканирования ClamAV — закрытая, нет публичных ссылок на фото. Если ClamAV не отвечает, заказ не выдаётся рабочему приёмщику.
- Готов черновик правовой политики с полями для заполнения; GitHub CI блокирует указание production URL, пока юридическая заглушка не заменена реальной ссылкой privacy.html.
- **Повторный локальный сквозной тест** обновлённого FastAPI на Windows прошёл: JPG + PDF → локальный API → агент → отдельная QA-папка → SHA-256 → статус received, без использования клиентских файлов и без изменений D:\\2026. Тестовый сервер завершён.
- CI последнего проверенного набора на 21.11.2026: 24 теста прошли, 1 пропущен, браузерные проверки мобильной и десктопной версий, Windows-тесты и проверка Compose/Caddy — успешно. См. GitHub Actions в PR №11.

**Итог:** дизайн А и программный защищённый шлюз подготовлены; реальный интернет-приём в РФ НЕ запущен. Для запуска требуется реальный VPS/домен и согласованные сведения об операторе/сроках хранения. Основная ветка main и действующий QR/старые боты без изменений.
