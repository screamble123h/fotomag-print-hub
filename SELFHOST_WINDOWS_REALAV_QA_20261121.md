# FotoMag — Windows сервер: настоящий ClamAV и проверка доставки

21.11.2026. Локальная подготовка на рабочем ПК FotoMag.

## Проверено на ПК

- Проверен публичный IPv4 интерфейса WAN Netis N2Mv2. Бесплатное имя sslip.io со встроенным IPv4 разрешается в этот адрес. Это не доказывает внешнюю доступность TCP:80/443; при смене PPPoE IP имя изменится. Адрес и серийные номера роутера не публикуются в GitHub.
- ClamAV 1.4.7 LTS из официального релиза Cisco Talos (192031028 байт, SHA256 f2c027084974674dbd8db5ae57fa3f14bde0a54450cafa10b7cc05ad20131ecf) распакован в отдельном каталоге D:/FotoMag_Direct_Upload_Channel/selfhost_20261121. Не заменяет 360 Total Security.
- FreshClam скачал актуальные базы daily.cvd, main.cvd и bytecode.cvd. Сканер clamd доступен только на 127.0.0.1:3310. Проверено PONG; чистый образец OK; безвредный контрольный EICAR найден (FOUND). С LAN-сети порт не доступен.
- Официальный Caddy 2.11.9 для Windows (18384117 байт, SHA256 ad93112d335ee687100c4c9f11bced16ca590377976b7fe7883882b9e797e472) загружен и проверен. Два файла конфигурации прошли caddy validate. Локальный Caddy на 127.0.0.1:19001 проксирует API и отвечает 404 на посторонние пути.
- В ходе проверки выявлена опасность: без явного bind Caddy слушал LAN-интерфейс. Этот тестовый экземпляр немедленно остановлен, локальная конфигурация исправлена на bind 127.0.0.1; повторный тест подтвердил отсутствие доступа через LAN.
- Основной FotoMag API работает на 127.0.0.1:19000, но FOTOMAG_UPLOAD_MODE=disabled, не принимает заказы. GET /api/health => accepting_uploads false, POST /api/orders => 503, неавторизованный GET /api/agent/overview => 401.
- Локальный секрет агента создан с защищённым ACL и не публиковался; private_queue защищена отдельными NTFS ACL.
- Отдельный временный QA API 127.0.0.1:19002 в production-режиме передал два синтетических файла PNG+PDF через РЕАЛЬНЫЙ ClamAV, очередь и код Windows receiver в отдельный тестовый архив на D:. Байты и SHA-256 совпали, ACK получен. Тестовый receipt FM-W-20261121-1EF5FE3; локальный отчёт QA_REAL_CLAMAV_E2E_RESULT.txt. Тестовый production QA после проверки остановлен. Ни один реальный клиентский файл не использовался.

### Фактические порты после тестов

127.0.0.1:3310 — ClamAV. 127.0.0.1:19000 — API disabled. 127.0.0.1:19001 — Caddy loopback. 19002, 80, 443, 8000 — не слушают.

## Осталось для безопасного публичного запуска

1. Проверить входящий TCP 80/443 из мобильного интернета и настройку NAT роутера Netis. Ограничивать публичный доступ только TLS proxy, не раскрывая 3310, 19000, RDP/SMB или личный архив.
2. Подключить автоматический публичный HTTPS-сертификат Caddy, проверить его продление. При смене PPPoE IP потребуется динамический DNS, для которого может понадобиться бесплатный аккаунт; не брать выходной VPN IP.
3. Утвердить политику обработки персональных данных, сведения оператора и сроки хранения; проверить 152-ФЗ. До этого реальные фото паспортов и документы не принимать.
4. Испытать мобильную отправку и загрузку больших файлов, устойчивость ответов при включении/выключении Iblis TUN, сбои и нагрузку.
5. После успешной проверки включить контролируемый автозапуск Windows, указать реальный HTTPS API URL и CSP в GitHub Pages (дизайн A). QR и три прежних бота оставить без изменений.

Статус: REAL_AV PASS; REAL_AV_E2E_LOCAL PASS; CADDY_LOCAL PASS; PUBLIC_TLS NOT RUNNING; NETIS_NAT NOT CONFIGURED; CUSTOMER_UPLOAD DISABLED. Автозапуск пока не включён, локальные процессы будут остановлены перезагрузкой ПК.
