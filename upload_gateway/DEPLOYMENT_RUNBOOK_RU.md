# FotoMag — безопасное развёртывание защищённого приёмника (Runbook)

**Статус 21.11.2026:** код, дизайн А и локальный искусственный тест есть; VPS и публичный HTTPS-домен НЕ подключены. Это инструкция, а не свидетельство работающего публичного приёма.

## Архитектура

QR → GitHub Pages (только HTML/CSS/JS) → HTTPS API на отдельном VPS в РФ → SQLite и закрытые бинарные файлы → ClamAV в приватной сети → исходящий HTTPS-опрос с DESKTOP-P6L7HTI → D:/2026/MM/DD/Напрямую/имя/номер.

Три канала VK/MAX/Telegram не изменяются; нет автопечати, прямого доступа из интернета к диску D: и публикации документов в GitHub.

## Рекомендуемые ресурсы российского VPS

- ОС Linux LTS, не меньше 2 vCPU, **8 ГБ RAM** (ClamAV рекомендует 4 ГБ только для своего контейнера), SSD от 60 ГБ, отдельные зашифрованные резервные копии.
- Провайдер подтверждает размещение основного хранилища и резервных копий в РФ. Проверить договор обработки персональных данных и ответственность сторон.
- HTTPS-домен, доступный мобильным клиентам из Ижевска. Доступ к VPS по SSH-ключам, запрет входа по паролю, ограниченный вход администратора.
- Файрвол VPS: наружу только TCP 80 и 443 (SSH исключительно из административного диапазона). Ни 8000, ни 3310 НЕ публиковать.
- Для DNS/сертификата нужен реальный домен. В файле примеров files.example.ru — заглушка, не действующий адрес.

## Перед развёртыванием

1. Утвердить сведения юридического оператора, политику/согласие и срок хранения (см. PRIVACY_POLICY_DRAFT_RU.md). Проверить применимость 152-ФЗ и уведомления РКН.
2. Установить обновления ОС, Docker и Docker Compose; настроить резервирование, мониторинг, ограничение доступа и план восстановления.
3. В каталоге upload_gateway на VPS создать локальный .env из .env.example. Выбрать реальный FOTOMAG_API_DOMAIN, а FOTOMAG_SITE_ORIGIN оставить https://screamble123h.github.io, пока сайт там.
4. Создать случайный FOTOMAG_AGENT_TOKEN не короче 32 символов. Секрет хранить только на VPS и на ПК FotoMag, не в GitHub, переписке и клиентском HTML. Защитить .env правами 0600.
5. Начать с FOTOMAG_UPLOAD_MODE=disabled. Запустить docker compose -f upload_gateway/compose.yaml up -d --build. Проверить сервис и антивирус без реальных клиентских файлов.
6. Проверить, что запрос GET /api/health возвращает accepting_uploads=false в disabled, а API POST /api/orders отвечает 503.
7. Включить production ТОЛЬКО когда ClamAV отвечает PONG, антивирусное сканирование выявляет стандартный БЕЗВРЕДНЫЙ тест EICAR, а чистые файлы пропускает. Не открывать публике endpoint при ошибках антивируса.
8. Установить лёгкий агент на рабочий ПК с исходящим доступом только к конкретному API HTTPS. Не открывать на ПК порты и не менять каналы MAX/VK/Telegram.
9. Проверить передачу синтетических JPEG/PDF с внешнего мобильного интернета на VPS РФ, затем в D:/2026/MM/DD/Напрямую/клиент/заказ. Совпадение байтов SHA-256, один экземпляр файла, корректная дата Ижевска.
10. Проверить падение интернета, отключённый компьютер, повторную отправку, лимиты, неверный Origin, попытку загрузить EXE и конфликт имени.
11. Только после этого создать юридически утверждённую privacy.html с реальными реквизитами и ссылку в согласии, установить API URL в index.html и разрешить точно этот origin в CSP connect-src. GitHub CI должен пройти полностью.
12. Переключить PR №11 из Draft после сквозной проверки и согласования; развернуть в main при сохранении старых ссылок. QR менять не требуется, если URL GitHub Pages остаётся прежним.

## Гарантии отключения и эксплуатации

- Начальное значение FOTOMAG_UPLOAD_MODE=disabled; изменение режима требует явного действия оператора.
- Сервер должен проверять живой ClamAV на /api/health: если он недоступен, сайт блокирует кнопку.
- При ошибке проверки файл не попадает в рабочую очередь. Тестовый режим staging никогда не должен быть публичным.
- Квоты: до 10 файлов, 25 МиБ каждый, 100 МиБ на заявку; на сервере предусмотрены суточный лимит 5 ГиБ и запас диска 3 ГиБ. Можно изменить после нагрузочных испытаний.
- Прямой HTTP-доступ к порту 8000 и ClamAV 3310 запрещён.
- Временная очередь и резервные копии требуют согласованного срока хранения. Нынешняя система ничего не удаляет автоматически, чтобы не нарушить запрет владельца на удаление файлов без согласования.
- Ежедневная проверка очереди и оставшегося места, журнал ошибок без телефонов/имён/имён файлов; журнал доступа не должен хранить токены.
- Число зарегистрированных заказов с одного IP (за час) повышено до 60, чтобы несколько клиентов на AGFA/общем Wi-Fi не блокировали друг друга; дополнительно требуется внешний WAF или сетевой ограничитель и мониторинг.
- Docker на текущем рабочем ПК имеет лимит около 3 ГБ, недостаточный для ClamAV: запуск тяжёлого контейнера там запрещён. Тестировать контейнер на отдельном VPS/в GitHub CI.

## Достоверность проверок

CI проверяет синтаксис Docker Compose и Caddy, клиентскую страницу, REST API, ClamAV-протокол на искусственном сокете, даты и клиентские папки на Windows. Это **не** означает реального продакшен-теста ни антивируса, ни российского VPS.
