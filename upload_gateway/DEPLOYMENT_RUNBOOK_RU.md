## Перед запуском

1. Сделайте закрытую копию рабочих конфигураций и сверьте занятость портов. Порты 80 и 443 обслуживают действующее оборудование. Для приёмника отведён только TCP 8443. Утвердите у провайдера бесплатного DNS возможность коммерческого использования. Обновляйте запись A из адреса WAN на маршрутизаторе, включая проверку при смене VPN на компьютере.
2. Получите сертификат по DNS-01 с автоматическим продлением. Локальные секреты DNS, API и закрытый ключ сертификата должны читаться только нужной учётной записью. Проверьте с мобильной сети имя, цепочку и срок действия сертификата.
3. На Windows используйте отдельные учётные записи и ACL. Caddy принимает внешние соединения, API, ClamAV и интерфейс приёмщика слушают только loopback. Доступ на запись в рабочий архив нужен приёмщику. Сохраните раздельные каталоги для тестовой и рабочей очередей. Для локальных интеграционных тестов существует отдельный Compose-пример.
4. Публичный Caddy передаёт только клиентские маршруты health, orders, files, submit и status. Маршруты агента, документация API и панель Caddy остаются локальными. Заголовок X-FotoMag-Client-IP задаёт сам прокси. Сверьте шаблон в рабочей установке с [конфигурацией приложения](Caddyfile).
5. Для создания заказа браузер отправляет JSON, затем каждый файл отдельным PUT без multipart. Верхняя граница тела такого запроса — 26 214 400 байт. API проверяет также фактическую длину, число файлов, сумму по заявке, оставшееся место и суточную квоту. Проверяйте оба уровня точными размерами.
6. Выполните [правовую подготовку](PRIVACY_POLICY_DRAFT_RU.md). Утверждённый идентификатор редакции должен совпадать в форме, странице согласия и локальной переменной FOTOMAG_CONSENT_VERSION (формат YYYY-MM-DD или YYYY-MM-DD-v2). Архивируйте утверждённые тексты по редакциям. Черновик блокирует production.
7. Проверьте у поставщика QR-страницы условия использования коммерческой формы до публичного размещения. Укажите фактический разрешённый HTTPS origin клиента в CORS и единственный HTTPS origin API в CSP формы. Доступ к служебному токену предусмотрен только на ПК.

## Форма на том же Caddy

На компьютере фотоцентра можно отдавать утверждённый портал и принимать публичные запросы API на одном HTTPS-адресе с портом 8443. Для страницы и API используется один сертификат. Схема не требует размещать коммерческую форму на GitHub Pages. Правила для действующей страницы и её роли в маршруте QR опубликованы в [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). Размещение ссылки или перенаправления требует оценки назначения самой страницы. При недоступности ПК посетитель, у которого страница ещё не открыта, увидит сообщение браузера об ошибке соединения. В уже открытой форме доступность проверяется через API.

1. Из проверенной ветки соберите новый каталог выпуска вне репозитория. Ниже приведён пример адреса. Подставьте подтверждённое имя своей зоны и свободный путь на ПК.

   ```powershell
   py -3 upload_gateway/build_selfhost_form.py --origin https://files.example.org:8443 --output D:/FotoMagPortal/releases/v1
   ```

2. Внутри выпуска лежат `site` с клиентскими файлами и `Caddyfile.form` с разрешёнными путями GET/HEAD. Локальной учётной записи Caddy достаточно чтения. Храните резервные копии, логи, настройки, сертификаты и файлы заказов в других каталогах. Сборка оставляет действующие режим приёма и службы под управлением оператора. По умолчанию API работает в режиме disabled.
3. В уже проверенный блок HTTPS сайта на 8443 добавьте перед общим правилом 404 строку импорта с двумя абсолютными путями к новому выпуску:

   ```caddyfile
   import "D:/FotoMagPortal/releases/v1/Caddyfile.form" "D:/FotoMagPortal/releases/v1/site"
   ```

   Сохраните правила закрытых маршрутов и привязку API и ClamAV к loopback. `FOTOMAG_SITE_ORIGIN` в конфигурации API должен точно совпадать с `--origin`, включая порт. В форме CSP ограничивает обращения соединениями со своим origin. Токены службы в сборке формы не используются.
4. До открытия порта проверьте собранную конфигурацию командой `caddy validate` с параметрами рабочего экземпляра. На изолированном слушателе проверьте страницу, открытие раздела загрузки, политику, стили и шрифты. Убедитесь, что служебные маршруты и произвольные файлы получают HTTP 404. В режиме disabled создание нового заказа должно получить HTTP 503 при корректном тестовом запросе.
5. Для перехода на новый выпуск соберите новый каталог и переключите оба пути импорта одновременно. До включения приёма завершите проверку с реального телефона, согласование политики и остальные пункты приёмки. Предыдущий каталог можно использовать для отката.

## Приёмка и работа

- Для испытаний используйте отдельную очередь и искусственные изображения и документы. Локальный staging не предназначен для публикации. Внешнюю проверку проводите с доступом, ограниченным участниками испытания.
- На телефоне с выключенным Wi-Fi откройте обычный QR, проверьте работу приложения при обоих состояниях VPN на ПК, отправьте JPG, PDF и несколько файлов. Сверьте номер заявки и SHA-256 в полученной папке архива. Принятие сервером и подтверждение записи на диск показываются отдельно.
- Проверьте реакцию на разрыв связи, повторную доставку, недоступный антивирус, тестовый образец EICAR, исчерпание диска и выключенный ПК. При повторе получатель проверяет контрольную сумму перед подтверждением. Существующие файлы не перезаписываются.
- Включайте штатную работу после этих испытаний. Для аварийной остановки установите локально FOTOMAG_UPLOAD_MODE=disabled и перезапустите только процесс API. Проверьте внешний health и отказ создания заявки. Доступные клиентские каналы остаются на QR-странице.
- Настройте старт Windows-служб с минимальными правами, обновление сигнатур, контроль диска, сроков сертификата, состояния динамического DNS, задержки очереди и ошибок. Протестируйте восстановление базы SQLite и соответствующих файлов из одной согласованной резервной копии в отдельном каталоге. Сроки, доступ, удаление и обращения определяет утверждённая политика.
