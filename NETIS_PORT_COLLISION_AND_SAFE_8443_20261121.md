# FotoMag — Netis 21.11.2026: безопасное подключение без конфликта с видеонаблюдением

**Статус:** внешняя загрузка для клиентов НЕ включена. Основной сайт, QR, VK, MAX, Telegram без изменений.

## Результаты проверки Netis N2Mv2 на реальном ПК

1. Публичный WAN IPv4 Netis подтверждён ранее скриншотом владельца; существующая GitHub Pages статическая страница FotoMag работает независимо от локального ПК. Приватные локальные адреса и точный WAN IP в публичном GitHub не размещаются.
2. Внешние TCP **80 и 443 уже перенаправлены на отдельный активный LAN-хост** с меткой **RLN8-410** — модель сетевого видеорегистратора Reolink. Устройство действительно отвечает на 80/443. Существующие правила имеют постоянную аренду (lease=0).
3. **Ничего не изменено в видеорегистраторе.** Переназначение публичных 80/443 на рабочий ПК могло бы отключить доступ к камерам и создать риск безопасности. Этого не делали.
4. Проверено, что альтернативные внешние TCP **8443** и **18489** отсутствовали в таблице переадресаций.
5. Выполнено короткое тестовое правило **только** для проверки TCP 18489 в отдельный статический текстовый тестовый обработчик, без данных клиентов. Netis необычно вернул ошибку SOAP 501, однако правило появилось с арендой 120 сек. Проверены метка и внутренний IP только нашего теста.
6. **Тестовый порт сразу после проверки удалён**, SOAP DeletePortMapping вернул 200. Повторная независимая проверка GetSpecificPortMappingEntry подтвердила: внешний 18489 больше не перенаправляется, а 80 и 443 остались на своём прежнем устройстве.
7. Удалённая веб-проверка нестандартного URL не смогла подтвердить внешнюю доступность тестового сервера, поэтому **внешняя связь не доказана**.
8. На PC Desktop Commander не имеет административного токена Windows. Windows Firewall включён. Без UAC и отдельной проверки безопасности не открывали никаких постоянных входящих правил.
9. Локальная связка FotoMag API (disabled), ClamAV, Caddy (loopback) и Windows receiver по-прежнему работает в безопасном закрытом режиме. Никаких настоящих документов при маршрутизации Netis не принималось.

## Бесплатный путь с сохранением 80/443 для камер

- Использовать отдельный публичный TCP **8443**; внутри ПК — выделенный HTTPS Caddy, API только на 127.0.0.1, ClamAV только на 127.0.0.1.
- Так как стандартные внешние 80/443 заняты, для **доверенного браузером HTTPS-сертификата** использовать DNS-01 challenge с бесплатной управляемой зоной/поддоменом (например, dynv6, где нужен аккаунт/токен владельца).
- Прежде чем включать правило Netis 8443, настроить публичный сертификат, входной Windows Firewall только для HTTPS Caddy, обязательную антивирусную проверку, ограничения объёма/числа запросов, правила работы с клиентскими данными. Проверить стабильность VPN NekoBox/Iblis.
- Сначала тестировать извне на синтетических файлах, затем и только затем разрешать публичный API и GitHub Pages дизайн А. QR остаётся прежним.

## Соседняя задача безопасности

Переадресации 80/443 на видеорегистратор через UPnP несут потенциальный риск его доступности из интернета. Можно отдельно проверить, требуется ли этот доступ и защищён ли регистратор. **Не отключать UPnP и камеры без согласования**.
